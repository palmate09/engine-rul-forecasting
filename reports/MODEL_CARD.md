# Model Card — C-MAPSS FD001 RUL Estimator

## 1. Model details

| Field | Value |
|---|---|
| Model name | C-MAPSS FD001 RUL Estimator |
| Version | 1.0 |
| Model type | Ridge regression (L2-regularized linear model) |
| Task | Remaining useful life (RUL) regression |
| Target | Cycles to failure, capped at 125 |
| Input | Multivariate sensor history from a turbofan engine |
| Output | Point estimate of RUL in cycles, clipped to [0, 125] |
| Artifact | `models/rul_model.joblib` |
| Training date | Generated by `python -m src.train --subset FD001` |

### Pipeline

```text
median imputation -> standardization -> Ridge(alpha=1.0)
```

The saved joblib bundle contains the fitted pipeline, the 213 feature names, the
15 retained sensor columns, the dropped sensor list, window sizes, RUL cap,
subset, selected model name, metrics, and training timestamp.

## 2. Intended use

### Primary intended use

- Educational demonstration of RUL regression on a public benchmark.
- Comparing feature engineering and regression algorithms under an engine-level
  validation protocol.
- A decision-support prototype that prioritizes engines for inspection.

### Out-of-scope use

- Real aircraft maintenance or airworthiness decisions.
- Fleet-wide deployment without field validation.
- Fault diagnosis or component-level attribution.
- Operating conditions or fault modes not represented in FD001.
- Safety-certified or autonomous maintenance scheduling.

## 3. Training data

| Field | Value |
|---|---|
| Dataset | NASA C-MAPSS FD001 |
| Source | NASA Prognostics Data Repository |
| Training engines | 100 |
| Training rows | 20,631 |
| Test engines | 100 |
| Test rows | 13,096 |
| Operating conditions | 1 (sea level) |
| Fault modes | 1 (HPC degradation) |
| Sensors | 21 raw, 15 retained |
| Target cap | 125 cycles |

Six sensors are constant in FD001 and removed: `s1`, `s5`, `s10`, `s16`,
`s18`, `s19`.

Full dataset details are in [`DATA_CARD.md`](DATA_CARD.md).

## 4. Features

For each of 15 sensors:

- first difference;
- rolling mean, standard deviation, minimum, and maximum over 10, 30, and 50
  cycles.

Plus the three operational settings. Total: 213 features. All rolling features
are backward-looking. The engine ID is not a feature. The cycle index is excluded
by default.

## 5. Evaluation

### Validation protocol

- 80 training engines / 20 validation engines.
- Each validation engine truncated at five random cycles (25%–100% of life).
- 100 validation predictions.
- Model selected by average rank of RMSE and NASA mean score.
- Official test set not used for selection.

## 6. Limitations

1. **Simulated data.** C-MAPSS is not a physical fleet.
2. **One operating condition.** FD001 is sea level only.
3. **One fault mode.** The model does not generalize to other degradation modes.
4. **Capped target.** Predictions above 125 are clipped; raw-target errors are
   larger for high-RUL engines.
5. **No uncertainty.** The model returns a point estimate, not a calibrated
   prediction interval.
6. **Late predictions.** 50 of 100 test predictions are late. The mean error is
   slightly early, but individual late errors are costly.
7. **Small validation set.** Twenty engines is limited for hyperparameter
   selection.
8. **No cost model.** Priority thresholds and the 10% planning buffer are
   illustrative.
9. **No drift monitoring.** A deployed system needs input checks and retraining.
10. **Post-hoc ablation.** The ablation uses the test set for reporting, not for
    model selection.

## 7. Ethical considerations

- **Safety:** RUL under-estimation can cause unnecessary maintenance;
  over-estimation can cause in-service failure. The model must be decision
  support, with human oversight and conservative buffers.
- **Accountability:** A qualified engineer remains responsible for maintenance
  decisions.
- **Transparency:** The target cap, split protocol, features, metrics, and
  failure cases are documented.
- **Privacy:** No personal data are used.
- **Research integrity:** Results are benchmark results on simulated data, not
  evidence of field readiness.

## 8. Recommendations for use

1. Use predictions to prioritize inspection, not to authorize continued
   operation.
2. Apply a conservative planning buffer; tune it with real cost data.
3. Review engines with unusual sensor histories or high model disagreement.
4. Add calibrated uncertainty before deployment.
5. Monitor input distributions and retrain when they drift.
6. Revalidate on the target fleet and operating conditions.
7. Keep the model version, training data, and metrics under configuration
   control.

## 9. Maintenance and reproducibility

```bash
# Retrain
python -m src.train --subset FD001

# Run tests
python -m unittest discover -s tests -v

# Rebuild the report
python scripts/build_report.py
```

The pipeline uses a fixed seed (42), deterministic feature definitions, and a
saved bundle with metadata. Metrics and predictions are written to `results/`.
